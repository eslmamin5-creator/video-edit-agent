# video-edit-agent

**اتكلم معاه بلغتك العادية — عربي أو إنجليزي — وهو يحوّل فيديو خام، أو
سكربت، أو مجلد مشاهد، لفيديو جاهز ومترجم.** يعمل بالكامل دون اتصال إذا

## إيه اللي يقدر video-edit-agent يعمله؟

افتح Claude Code، ثبّت/شغّل `video-edit-agent`، كلّمه بشكل طبيعي، وهيطلعلك
فيديو — مش لازم تقرأ توثيق تقني أو تحفظ أوامر CLI الأول. في ثلاث سير عمل،
وإنت بس تقول اللي عايزه بكلامك، والوكيل هو اللي يحدد المسار المناسب:

| عندك... | تقول (مثال) | هيشغّل |
|---|---|---|
| تسجيل خام واحد (حديث مباشر، إعلان) | "عدل الفيديو ده" / "Edit this video" | **Editor** |
| سكربت أو فكرة، من غير تصوير لسه | "اعمل فيديو من السكربت ده" / "Create a video from this script" | **Creator** |
| كذا مشهد مصوَّر بالفعل | "اجمع المشاهد دي" / "Assemble these scenes into one film" | **Assembler** |

لو اللي إنت عايزه مش واضح فعلًا، الوكيل هيسألك سؤال توضيحي واحد قصير بدل
ما يخمّن.

## Editor / Creator / Assembler

### Editor — تسجيل خام واحد يدخل، فيديو جاهز يخرج
لتسجيل حديث مباشر أو إعلان موجود بالفعل. يشمل: التفريغ، تنظيف الصمت
والتكرار والبدايات الفاشلة، الترجمات (تشكيل عربي واتجاه RTL، تظليل الكلمات)،
الرسوم المتحركة، تخطيط المواد الإضافية (B-roll)، وضع رسومات خلف الشخص لو
متاح، أسلوب الهوية التجارية، فحص الجودة، والتصدير النهائي. تشغيل عبر
`videoedit edit <video>`.

### Creator — سكربت أو فكرة يدخل، فيديو جاهز يخرج
لما ما يكونش عندك تصوير لسه، بس فكرة أو سكربت مكتوب. يشمل: تحليل السكربت،
تخطيط المشاهد، التحليل، لوحة القصة (storyboard)، خطة المواد، MasterTimeline،
معالجة الحركة، التصدير، فحص الجودة. تشغيل عبر `videoedit create <script>`.

### Assembler — كذا مقطع موجود يدخل، فيلم واحد يخرج
لمجلد مشاهد مصوَّرة بالفعل. يشمل: اكتشاف المشاهد، الحفاظ على الترتيب،
قصة أولية سريعة، تخطيط الاستمرارية، انتقالات حقيقية، تلاشي صوت متقاطع،
وتطبيع مستوى الصوت. تشغيل عبر `videoedit assemble <scenes_dir> --rough` ثم
`--finish`.

## أهم الميزات

- **ذكاء المونتاج** — مونتاج مبني على النص المفرَّغ، معالجة الصمت والتكرار
  والبدايات الفاشلة، خطة مونتاج (EDL) قابلة للفحص، قرارات مونتاج قابلة
  لإعادة التصدير (غيّر قرار، وأعِد التصدير — من غير ما تعيد خط الأنابيب
  كله)، وذاكرة `project.md` دائمة توضح قرارات الوكيل وأسبابها.
- **العربية** — ترجمات RTL، تشكيل عربي، تظليل كلمات على طريقة الكاراوكي،
  الحفاظ على المصرية/الخليجية/السعودية/الفصحى، نصوص عربي/إنجليزي مختلطة،
  وبدون أي تحويل لهجة مخفي، أبدًا.
- **الحركة (Motion)** — محرك حركة بسيط مدمج يعمل دون اتصال دائمًا، تصدير
  Remotion اختياري، تراجع تلقائي لمحرك الحركة، تقرير حالة التركيب خلف
  الشخص، وأسلوب مرتبط بالهوية التجارية.
- **المواد الإضافية (B-roll)** — تخطيط مع بدائل تلقائية، مسار كامل دون
  اتصال، وتحسين سحابي اختياري (صور/فيديو Gemini) عند توفر المفاتيح.
- **خط أنابيب Creator** — سكربت ← تحليل ← مشاهد ← لوحة قصة ← خطة مواد ←
  جدول زمني ← تصدير.
- **خط أنابيب Assembler** — قصة أولية ← إتمام، مع الحفاظ على ترتيب
  المشاهد، وتخطيط استمرارية، وانتقالات حقيقية، وتلاشي صوت متقاطع، وتطبيع
  مستوى الصوت.
- **ملفات الهوية التجارية (Brand Profiles)** — ألوان وخطوط وأنماط ترجمات
  قابلة لإعادة الاستخدام لكل هوية، بدون أي تعديل في الشيفرة المصدرية.
- **قابلية الفحص** — كل مرحلة ملف عادي تقدر تفتحه: `project.md`، النص
  المفرَّغ، خطة المونتاج، MasterTimeline، خطط الحركة/المواد/الجودة،
  والفيديو النهائي.

## العربية أولًا، مع الحفاظ على اللهجة

- الوكيل يفرّغ بالضبط ما قيل — مصرية، خليجية، سعودية، فصحى، أو مزيج
  عربي/إنجليزي — ولا يعيد كتابة اللهجة أو "يصلّحها" أو يحوّلها لأخرى أبدًا.
  الصوت المصدر هو المرجع النهائي (`language/dialect_guard.py`).
- **ده مستقل تمامًا عن اللغة اللي بتكلم بيها الوكيل.** لو كتبت لـ Claude
  Code بالعربي، هيرد عليك بعربي طبيعي في كل حاجة (الإعداد، الحالة،
  الأسئلة، الشرح)؛ ولو كتبت بالإنجليزي، هيرد بالإنجليزي. في الحالتين، نص
  الفيديو والترجمات بتفضل زي ما اتقالت بالظبط — الوكيل مايترجمش أو "ينضف"
  اللهجة أبدًا مجرد لأنك سألت بلغة مختلفة.
- الترجمات العربية تظهر باتجاه RTL بتشكيل صحيح، وتدعم تظليل الكلمات على
  طريقة الكاراوكي، وممكن تخلط نص عربي/إنجليزي في نفس السطر.

## دون اتصال مقابل السحابة

| | يعمل بدون أي مفتاح API | إيه اللي بيضيفه لما يتفعّل |
|---|---|---|
| التفريغ | نعم — Faster-Whisper محليًا | `GEMINI_API_KEY` / `ELEVENLABS_API_KEY` يفتحان تفريغ سحابي |
| الترجمات، تشكيل RTL، تظليل الكاراوكي | نعم، بالكامل محليًا | — |
| المونتاج (صمت/تكرار/بدايات فاشلة، EDL) | نعم، بالكامل محليًا | — |
| الرسوم المتحركة | نعم — محرك بسيط مدمج | Remotion (يحتاج Node/npm، بدون مفتاح API) لحركة أغنى |
| المواد الإضافية (B-roll) | مكتبة/تخطيط محلي احتياطي | توليد صور/فيديو Gemini لمواد بالذكاء الاصطناعي |
| فحص الجودة البصري | فحوصات محلية أساسية | رؤية Gemini لفحص جودة أغنى |
| ملفات الهوية، EDL، التصدير، Assembler (أولية/إتمام) | نعم، بالكامل محليًا | — |

لا يُطلب أي مفتاح API أبدًا لإتمام خط الأنابيب الأساسي. المفاتيح تُقرأ فقط
من متغيرات البيئة `GEMINI_API_KEY` / `ELEVENLABS_API_KEY` — لا تُكتب أبدًا
في ملف إعدادات، ولا تُسجَّل، ولا تُطبع من أي أمر.

## التثبيت عبر Claude Code

1. استنسخ (clone) أو ثبّت هذا المستودع داخل مجلد مهارات (skills) الخاص
   بـ Claude Code.
2. افتح Claude Code (أو أعد تشغيله).
3. قل: **"Set up video-edit-agent and verify it."**

يقوم Claude بإعداد كل شيء نيابة عنك: يكتشف نظام التشغيل وإصدار بايثون
متوافق (يفضّل 3.11)، ويبني بيئة تشغيل خاصة يملكها المشروع نفسه
(`.runtime/venv` — أبدًا بايثون النظام العام)، ويثبّت الحزمة الجاهزة للعمل
دون اتصال، ويتحقق من `ffmpeg`/`ffprobe` وNode/npm، ثم يعرض تقرير جاهزية
واضحًا (باللغة اللي بتكلمه بيها). لا يُثبِّت أبدًا برمجيات على مستوى النظام
دون إذن — إذا كان `ffmpeg` مفقودًا يعطيك الأمر الدقيق المناسب لنظامك
(`winget`/`choco`/`scoop` على Windows، وHomebrew على macOS، ومدير حزم
توزيعتك على Linux) وينتظر منك تشغيله بنفسك. لا يُطلب أو يُخزَّن أي مفتاح
API أبدًا.

مش محتاج تفهم بيئات بايثون الافتراضية أو حزم pip الإضافية أو توجيه
المزوّدين عشان تستخدم المسار ده.

## استخدام CLI التقني

### التثبيت من المصدر (للمستخدمين المتقدمين)

```bash
git clone https://github.com/eslmamin5-creator/video-edit-agent
cd video-edit-agent
python3 -m pip install -e .          # الحزمة الأساسية فقط
videoedit setup --profile full-local # يبني .runtime/venv ويثبّت الحزمة دون اتصال
```

على Windows (PowerShell)، بدون الحاجة لـ WSL:

```powershell
git clone https://github.com/eslmamin5-creator/video-edit-agent
cd video-edit-agent
py -3.11 -m pip install -e .
videoedit setup --profile full-local
```

يدعم `videoedit setup`:

| الأمر | ما يفعله |
|---|---|
| `videoedit setup` | إعداد كامل بالحزمة الموصى بها `full-local` (دون اتصال). |
| `videoedit setup --profile local\|subject\|motion\|core` | إعداد بحزمة تثبيت أضيق. |
| `videoedit setup --check` | للقراءة فقط: يعرض الجاهزية دون أي تغيير. |
| `videoedit setup --repair` | يعيد بناء بيئة التشغيل الخاصة من الصفر بالكامل، حتى لو بدت سليمة حاليًا؛ لا يمس أي شيء خارج `.runtime/`. |

إعادة تشغيل `videoedit setup` آمنة دائمًا — فهي متكررة النتيجة (idempotent)
وتعيد استخدام بيئة سليمة بدلًا من إعادة التثبيت.

التثبيت من PyPI (`pip install video-edit-agent`) لا يزال يعمل للحزمة
الأساسية ولأي إضافة فردية (`pip install "video-edit-agent[local]"`)، لكن
التثبيت من GitHub/المصدر متبوعًا بـ `videoedit setup` هو المسار الرسمي
المدعوم بالكامل — وPyPI ليس الطريقة الوحيدة.

**أنظمة التشغيل المدعومة:** Windows (PowerShell، بدون WSL)، macOS، Linux.
**بايثون:** يتطلب 3.10 فأعلى؛ يُفضَّل 3.11 ويُختار تلقائيًا عند توفره.
**ffmpeg/ffprobe:** مطلوبان لأي تصدير؛ يكتشفهما `videoedit setup`/`doctor`
ويقدّمان إرشادات تثبيت دقيقة عند غيابهما — لا يُثبَّتان تلقائيًا أبدًا.
**Node/npm:** اختياريان — مطلوبان فقط لمحرك الرسوم المتحركة Remotion؛ محرك
الحركة المدمج البسيط يعمل بالكامل دون اتصال بدونهما.
**مفاتيح API:** اختيارية دائمًا. عدم وجود أي مفتاح هو إعداد مدعوم بالكامل
ويعمل فعليًا.

شغّل `videoedit doctor` في أي وقت لعرض جدول القدرات الكامل وملخص آخر تشغيل
لـ `videoedit setup`.

### بداية سريعة

```bash
videoedit setup           # إعداد لمرة واحدة: بيئة تشغيل خاصة + حزمة دون اتصال + فحص القدرات
videoedit doctor          # عرض جدول القدرات الكامل
videoedit edit my_take.mp4
```

تجد المخرجات داخل مجلد `edit/` بجانب الفيديو المصدر: `final.mp4`،
`transcript_unified.json`، `edl.json`، `captions.ass`، `project.md`، وملفات
خطط الجودة/المواد الإضافية/الرسوم المتحركة بصيغة JSON.

### الأوامر

| الأمر | الوظيفة |
|---|---|
| `videoedit edit <video>` | تشغيل خط الأنابيب الكامل: تفريغ -> قص -> ترجمة -> مواد إضافية -> رسوم متحركة -> تصدير -> جودة |
| `videoedit create <script>` | تحويل نص إلى لوحة قصة -> خطة مواد -> رسوم متحركة -> تصدير -> جودة |
| `videoedit assemble <scenes_dir> --rough` | بناء قصة أولية سريعة من مجلد مشاهد مصوَّرة مسبقًا |
| `videoedit assemble <scenes_dir> --finish` | إتمام الفيلم: انتقالات حقيقية + تطبيع الصوت بين المشاهد، مع إعادة استخدام خطة القصة الأولية |
| `videoedit doctor` | عرض جدول القدرات (ffmpeg، Node، المزوّدون، المحركات) |
| `videoedit providers` | عرض مزوّدي التفريغ والرسوم المتحركة وتوفرهم |
| `videoedit setup [--profile ...] [--check] [--repair]` | إعداد بيئة التشغيل الخاصة والتحقق من جاهزية البيئة |
| `videoedit config show / set` | عرض أو تعديل الإعدادات المتراكبة (بدون أي أسرار) |
| `videoedit brand init / validate` | إنشاء أو التحقق من ملف هوية علامة تجارية |
| `videoedit project inspect <dir>` | عرض ذاكرة `project.md` لمشروع ما |

## حالة القدرات (اعتبارًا من الإصدار v0.2.2)

حالة صادقة لكل قدرة، باستخدام ست فئات:
`VERIFIED LOCALLY` (اجتاز اختبار قبول محلي حقيقي وغير وهمي)،
`VERIFIED WITH CLOUD` (نجح استدعاء API حقيقي مباشر)، `OPTIONAL` (غير مطلوب
لخط الأنابيب الأساسي)، `FALLBACK AVAILABLE` (يتراجع بسلاسة إلى بديل يعمل)،
`NOT VERIFIED` (الشيفرة موجودة لكن لا يوجد دليل قبول حقيقي)، `REQUIRES API KEY`
(محظور حتى تضبط مفتاحًا). شغّل `videoedit doctor` لعرض حي لنفس الجدول خاص
بجهازك.

| القدرة | الحالة | ملاحظات |
|---|---|---|
| التفريغ المحلي (Faster-Whisper) | VERIFIED LOCALLY | خط أنابيب `videoedit edit` الكامل بدون اتصال يعمل من البداية للنهاية بدون أي مفتاح API. |
| تفريغ Gemini | REQUIRES API KEY | المهايئ مُنفَّذ ومُختبَر بوحدات اختبار؛ يُتخطّى الاستدعاء المباشر تلقائيًا ما لم يُضبط `GEMINI_API_KEY`. لم يُختبر مقابل الـ API الحقيقي في هذه البيئة. |
| تفريغ ElevenLabs | REQUIRES API KEY / OPTIONAL | غير مطلوب أبدًا لإتمام خط الأنابيب؛ يُتخطّى الاستدعاء المباشر تلقائيًا ما لم يُضبط `ELEVENLABS_API_KEY`. |
| الترجمات العربية (اتجاه RTL، التشكيل/الربط، تظليل الكاراوكي، مزيج عربي/إنجليزي، خطوط الهوية التجارية) | VERIFIED LOCALLY | اختبار قبول حقيقي بتصدير ffmpeg + ffprobe + فحص محتوى البكسل ناجح بالكامل (13/13 فحصًا؛ `scripts/arabic_acceptance.py`). |
| التعرف الصوتي (ASR) على كلام عربي حقيقي | NOT VERIFIED | لم يتوفر في هذه البيئة أي ملف صوتي/صوت عربي حقيقي لتشغيل اختبار قبول ASR مباشر؛ منطق الحفاظ على اللهجة نفسه مغطّى باختبارات انحدار آلية بدلًا من ذلك (حالات مصرية/خليجية/مختلطة). |
| رسوم Remotion المتحركة | FALLBACK AVAILABLE | تم اكتشاف Node/npm والتصدير ممكن عبر `npx`، لكن لم يُشغَّل ويُسجَّل أي تصدير قبول حقيقي في هذه البيئة (يعرض `videoedit doctor` "Verified: not yet"). |

## المخرجات وملفات المشروع

كل مرحلة في كل خط أنابيب هي ملف عادي قابل للفحص بجانب الفيديو/المشروع —
لا شيء مخفي داخل حالة غامضة:

`project.md` (ذاكرة قابلة للقراءة توضح القرارات وأسبابها)، `transcript_unified.json`،
`edl.json`، `captions.ass`، ملفات خطط الجودة/المواد الإضافية/الرسوم المتحركة
بصيغة JSON، و`final.mp4`.

## الأسرار

`GEMINI_API_KEY` و `ELEVENLABS_API_KEY` تُقرأ فقط من متغيرات البيئة. لا تُكتب
أبدًا في ملف إعدادات، ولا تُسجَّل، ولا تُطبع أبدًا من أي أمر، بما في ذلك
`doctor`.

## ملفات الهوية التجارية (Brand Profiles)

تعيش الهويات التجارية كمجلدات عادية تحت `brands/<name>/` (الألوان، الخطوط،
قائمة الكلمات الممنوعة، محرك الرسوم المتحركة المفضل، نمط الترجمات). لا حاجة
لتعديل الشيفرة المصدرية لإضافة واحدة:

```bash
videoedit brand init my_brand
videoedit brand validate my_brand
videoedit edit my_take.mp4 --brand my_brand
```

## القيود المعروفة

- التعرف الصوتي (ASR) على كلام عربي حقيقي وتصدير Remotion لم يتم التحقق
  منهما بعد باختبارات قبول حقيقية في هذه البيئة (انظر جدول القدرات أعلاه).
- قصّات J-Cut/L-Cut نظرية فقط، غير منفَّذة.
- HyperFrames ليس محرك حركة حقيقي قابل للتثبيت؛ الموجّه يتراجع دائمًا إلى
  محرك يعمل ويسجّل التراجع.
